# Adapty: полный отчёт о продукте, сценариях и API

*Дата: 7 ноября 2026 · Хакатон Adapty First Commit, Белград · Команда 10*

> **Коротко.** Обзор Adapty перед выбором идеи: что умеет продукт, кто и как им пользуется, что можно и чего нельзя через API, CLI и MCP. Для проекта важнее всего два вывода. Первый: через публичные API доступны только агрегаты, профили читаются по одному, поэтому Verdict Agent считает по группам пользователей, а не по каждому. Второй: старт и стоп A/B-теста необратимы, поэтому инструмент только читает, а остановку охраняет хук. Документ написан 7 ноября, до кода; дальше — справочник.

## 1. Что такое Adapty

Adapty — инфраструктура монетизации подписочных приложений. В ядре:

1. **Покупки.** SDK и бэкенд покупок для App Store, Google Play, Stripe, Paddle и кастомных сторов.
2. **Экраны.** No-code конструктор онбордингов и пайволов **Flow Builder** с нативным рендерингом.
3. **Эксперименты.** **Таргетинг** (placements → audiences → segments) и **A/B-тесты**.
4. **Аналитика.** Выручка, когорты, LTV, предсказания.
5. **Подписчики.** **CRM** с профилями и таймлайном событий.
6. **Интеграции.** Webhooks, MMP, продуктовая аналитика, мессенджеры, выгрузка в S3/GCS.

Вокруг ядра работают отдельные продукты: **Adapty Attribution** (облегчённый MMP), **Ads Manager** (Apple Search Ads), **Adapty Mail** (email-ретеншн) и **Adapty Finance** (аванс выплат от сторов).

**Что изменилось в 2026:**
- Появились **Developer CLI**, **MCP-сервер** (`mcp.adapty.io`) и **agent skills**: аккаунтом теперь можно управлять через AI-агентов.
- Старые Paywall Builder и Onboarding Builder **deprecated с 1 октября 2026**. Всё новое делается на Flows, им нужен SDK v4+.
- **Autopilot переименован в AI Growth Advisor.**

**Модель оплаты:**
- Pro: бесплатно до $5K выручки в месяц, дальше 1% от выручки.
- Enterprise (custom): хранение данных в US/EU, Slack-канал поддержки, выделенный CSM, кастомные SLA.

Платные дополнения:

| Дополнение | Стоимость |
|---|---|
| Refund Saver | 0,2% выручки |
| Ads Manager | 3,5% рекламного бюджета |
| Mail | 20% от дополнительной выручки |
| Attribution | По договорённости (custom) |

### 2.4 Эксперименты и AI

| Фича | Что делает | Роль |
|---|---|---|
| Regular A/B test | Флоу или пайволы в одном плейсменте, до 20 вариантов, веса | Growth |
| Crossplacement test | Один вариант на нескольких плейсментах, только новые пользователи, закрепление на 90 дней | Growth |
| No-paywall variant | Holdout через флаг `show_paywall=false` | Growth |
| Результаты | Revenue, probability to be best (P2BB), revenue per 1K users с интервалом, конверсии, ARPPU, ARPAS, рефанды. Байесовский подход: ARPU за 2 недели используется как прокси для ARPU за 12 месяцев | Growth, Analyst |
| Predictions в A/B | Модель gradient boosting предсказывает выручку на 1K пользователей на год вперёд. Нужны данные примерно за 2 недели | Growth |
| Остановка теста | Выбрать победителя, показать другой элемент или откатиться по приоритету аудиторий. Запущенный тест редактировать нельзя: Modify создаёт копию | Growth |
| AI Growth Advisor (бывший Autopilot) | По скриншоту пайвола, до 5 конкурентам, бенчмаркам 20k+ приложений и Pricing Index строит план гипотез и последовательных тестов. Работает **только для App Store paywall placements** | Growth, Exec |

- **Оплата:** `entered_grace_period`, `billing_issue_detected`.
- **Разовые покупки:** `non_subscription_purchase`, `non_subscription_purchase_refunded`.
- **Доступ:** `access_level_updated` (только в webhook).

## 3. Сценарии по ролям: что человек делает с Adapty каждую неделю

| Роль | Регулярные сценарии | Где теряется время, деньги или растёт риск |
|---|---|---|

Поддержка webhook-обработчика (дедупликация, порядок событий). Пересборка fallback-файлов к каждому релизу. Server-side grants и списание виртуальной валюты. Нет CI-токена для CLI |
| **Growth / продакт** | Смотрит Overview и flow funnel, ищет экран с худшим drop-off. Делает или правит флоу (AI Editor, Figma), локализует. Запускает, мониторит и останавливает A/B-тесты. Ведёт план гипотез из Growth Advisor. Настраивает аудитории, сегменты и win-back офферы | Нет правил остановки теста и калькулятора выборки: в документации прямо сказано «set your own threshold». Запущенный тест нельзя поправить. Предсказания пропадают при фильтре по A/B. Сегменты только с AND |
| **Аналитик** | Режет графики по атрибуции, странам, продуктам и флоу. Когорты, LTV, предсказания. Сверка с App Store Connect и Play Console. Выгрузка через Export API или S3 в BI | Нет сохранённых видов. Конверсии пересчитываются задним числом, и в документации сказано «снимки сохраняйте сами». В CSV когорт нет разбивки по странам. | **Фаундер / руководитель** | Еженедельный email-отчёт и пуши. Тренд MRR, ARR и churn. Окупаемость по когортам и предсказаниям. Аванс через Finance | Нет алертов на аномалии и объяснения «почему». **Важно для хакатона.** `adapty apps get <id> --json` возвращает `secret_key` приложения. Значит, логина в CLI достаточно, чтобы вызывать Server-side API и Export API. Ключ нельзя показывать на экране и коммитить в репозиторий.

### 4.1 Чего через публичные API сделать нельзя

1. **Нет списка, поиска и выгрузки пользователей.** Профили читаются по одному. Список пользователей можно получить только из S3-выгрузки или собрать самому из webhooks.
2. **Нет таймлайна событий пользователя.** Профиль отдаёт текущее состояние, а не историю. Event feed есть только в дашборде и хранится 2 недели.
3. **Не все события есть в webhooks.** Нет показа пайвола или экрана флоу, создания профиля, смены атрибута, входа в сегмент. Показы пайволов есть только в суточной выгрузке S3.
4. **Интеграции, ключи и подключение сторов нельзя настроить через API.**
5. **Нет стриминга сырых данных.** S3/GCS выгружает раз в сутки, BigQuery и Snowflake нет.
6. **Аналитика — только агрегаты.** Лимит 2 запроса/с, группировка по одному измерению, в Export API нет фильтра по A/B-тесту.
7. **Почти ничего нельзя удалить.** Тип плейсмента и store product ID не меняются. Старт, стоп и архивация A/B-теста необратимы. Поэтому для экспериментов на запись нужен **отдельный sandbox-приложение**.
8. **У сегментов только AND.** «Last seen» в CLI недоступен. Неизвестное значение фильтра молча принимается и ни с кем не совпадает.
9. **Server-side grant не виден в аналитике.** Если нужна выручка и события, используйте `setTransaction`.
10. **Некоторые роуты CLI могут отставать от бэкенда.** Skills сообщают о 405 на `flows update` и `segments create`.

## 6. Шероховатости: что раздражает в CLI и API

Это выжимка из 38 пунктов, собранных при прогоне CLI. Полезна и как источник идей, и как фидбек команде Adapty.

**Безопасность и идентификаторы**
1. `adapty apps get` печатает `secret_key` открытым текстом, флага маскировки нет. Это опасно при демонстрации экрана и при работе через AI-агентов.
2. Сущности ищутся только по UUID: `placements get main`, `access-levels get pro` и `products get lumen.weekly` возвращают «Invalid ID format». Developer ID и store ID не принимаются.

**Флаги и значения по умолчанию**
3. Нет приложения по умолчанию и переменной `ADAPTY_APP`. App ID передаётся тремя разными способами.
4. Флаги называются непоследовательно: `--product` и `--product-id`, `--metrics` и `--metric`, `--granularity` и `--period-unit`.
5. `ab-tests list` по умолчанию показывает только тесты флоу (`--type flow`). Варианта «all» нет.
6. `ab-tests metrics get ID` требует повторить `--type`, хотя тип известен по ID, иначе ошибка `ab_test_type_mismatch`.
7. Даты только абсолютные: `-30d` и `today` не принимаются.
8. Недельные бакеты отсчитываются от дня недели `--date-from`, это не ISO-недели. Незавершённый период никак не помечен.

**Вывод, ошибки и лимиты**
9. Пустой результат выглядит пятью разными способами, ошибки приходят в трёх JSON-форматах. Под `--json` ошибки уходят в stdout.
10. CLI не повторяет запрос после 429: из 23 вызовов `analytics chart` подряд два упали по троттлингу.
11. Лимиты описаны в трёх местах по-разному: README, `asa whoami` и документация.

**Модель данных**
12. Цен нет нигде: `price_usd` = 0 у всех продуктов, `product-prices list` пишет «No prices.», хотя аналитика показывает продажи по $49,99.
13. Чтобы связать плейсмент, продукт и цену, нужно много вызовов: `placements get` по каждому плейсменту, затем `flows config get` (60–150 КБ) с разбором внутреннего поля `_meta.screens.*.products`. Обратного поиска «в каких плейсментах этот флоу» нет.
14. В результатах вместо имён UUID: варианты A/B и сегменты в метриках подписаны идентификаторами.
15. У завершённого теста нет поля «победитель» или «причина остановки».

**Аналитика, которая не сходится**
16. Число плательщиков различается по отчётам: new subscriptions 914, funnel «Paid» 954, LTV-когорта 924, cohort subscribers 982.
17. `chart revenue --group-by segment_id` показывает итог $123 736 вместо $44 686, потому что пересекающиеся сегменты суммируются.
18. Воронка немонотонна: paywall shown 897 < trial 951 < paid 954.
19. Конверсии `view-trial` и `view-paid` равны 0% при 897 просмотрах.
20. Attribution отвечает 404 «App not found» вместо понятного «Attribution не подключён». ASA отвечает 402 на любое чтение.
